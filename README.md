**호스트와 친구 모두 v0.7.0으로 업데이트하세요.** 복구 절차가 달라 이전 버전과 함께 접속할 수 없습니다. 일시적인 연결 끊김은 게임 창과 진행 위치를 유지한 채 복구합니다. 공격 명령은 메모리 주소나 짧은 일부 데이터 대신 전체 스크립트의 지문과 내부 위치로 비교합니다. 아직 시험판이며 모든 기술·스테이지와 서로 다른 PC의 장시간 진행을 검증한 것은 아닙니다.

## 한글 싱글플레이

**`Single-Korean.cmd`**를 실행하면 서버·IP·방 코드 없이 혼자 시작합니다. 기존 **`Launch-RBO.cmd`**도 이제 같은 한글 싱글 실행기로 연결됩니다. 필요한 경우 게임 폴더를 입력하고, 타이틀에서 시작한 뒤 1P로 캐릭터를 선택하거나 만드세요. 2P·3P는 참가하지 않습니다.

플레이 UI·대사에 온라인과 같은 한글 패치를 적용합니다. `Settings-Online.cmd`에서 지정한 1P 키·화면·소리 설정을 사용하며 창 모드로 실행합니다. 키보드를 지원합니다.

| 모드 | 저장 위치 |
| --- | --- |
| 한글 싱글 | `saves/single/current.json` |
| 온라인 호스트 | `saves/host/current.json` |
| 온라인 친구 사본 | `saves/replicas/<저장 ID>/current.json` |

**싱글과 온라인의 캐릭터·진행은 서로 가져오거나 덮어쓰지 않습니다.** 처음 싱글을 실행하면 새 캐릭터 목록으로 시작합니다. 싱글에서도 캐릭터 슬롯을 여러 개 저장할 수 있으며, 다음 실행에는 싱글 저장만 이어서 사용합니다. 원본 게임의 개인 저장도 별도로 보존합니다.

게임이 원래 저장하는 시점의 데이터를 보관합니다. 전투 중 위치를 그대로 재개하는 저장은 아닙니다. 종료할 때는 **게임 창을 먼저 닫고** 실행기의 종료 안내를 확인하세요. 한 저장 폴더에서 싱글 실행기를 중복 실행할 수 없습니다. 업데이트할 때 `saves` 폴더 전체를 보존하면 싱글·온라인 저장 모두 유지됩니다.

## 온라인 실행과 시작

1. 위 실행용 ZIP을 받아 완전히 풉니다. `Code → Download ZIP`과 `Source code`는 실행용 패키지가 아닙니다. Python은 실행용 ZIP에 포함됩니다.
2. 호스트는 `Host-Online.cmd`를 실행하고 본인 포함 **2 또는 3명**을 선택합니다. Enter는 2명입니다.
3. 처음 실행할 때 각자 **일본어판 EX3 4.0의 `rbo_ex3.exe`와 `DATA`가 들어 있는 폴더**를 입력합니다. 다음부터는 기억한 폴더를 자동으로 사용합니다.
4. 친구는 `Join-Online.cmd`에서 호스트의 접속 주소·포트(기본 47624)·방 코드를 입력합니다.
5. 전원이 연결되면 게임 창이 함께 열립니다. 1P가 타이틀의 일반 게임을 Z로 시작합니다. 예전의 데모 자동 시작을 기다릴 필요가 없습니다.
6. 캐릭터 화면에서 **모두 Z로 참가**한 뒤 각자 저장 슬롯을 선택하거나 캐릭터를 만듭니다. 전원 참가 전에는 다음 단계로 넘어가지 않습니다.
7. 전원의 선택이 끝나면 **1P가 공통 메뉴에서 출발과 스테이지를 선택**합니다. 첫 지도 선택은 Stage 1이며, 클리어 후에는 다음 스테이지를 제안합니다.

게임 원본은 포함하지 않습니다. 참가자 모두 같은 본편·EX1·EX2·EX3 PAC 데이터가 필요합니다. 게임 파일이 다르면 연결을 거부합니다. 지원 실행 파일 SHA-256:

```text
05b14b047e49dabb026c96150f8d5aab497d20d9b2d52f5e59a8aef1af5b8dc0
```

## 게임 폴더 기억과 변경

- 처음 입력한 게임 폴더를 실행기 폴더의 `game-settings.json`에 기억합니다. 폴더 경로나 `rbo_ex3.exe` 경로를 붙여 넣을 수 있습니다. 다음 실행부터 경로를 다시 묻지 않습니다.
- Join·Host·싱글·설정 프로그램이 같은 선택을 사용합니다. 다른 게임 폴더로 바꾸려면 **`Select-Game.cmd`**를 열어 새 경로를 입력하세요. Enter는 현재 폴더를 유지하며, 선택만 바꾸고 게임은 실행하지 않습니다.
- 기억한 폴더가 이동·삭제되면 다시 선택합니다. 기억한 경로가 없거나 사용할 수 없을 때, 실행기 안의 `runtime/app`에 게임이 있으면 기존처럼 자동으로 사용합니다.
- 업데이트할 때 `game-settings.json`도 보존하세요. 새 실행기 폴더에 압축을 풀었다면 기존 설정 파일을 함께 옮겨야 기억한 경로가 유지됩니다. ZIP 안에서 직접 실행하지 말고 쓰기 가능한 폴더에 완전히 풀어 사용하세요.
- 개발용 `--game` 인자는 해당 실행에만 적용하며 기억한 경로를 덮어쓰지 않습니다. 게임 원본의 저장·키 설정은 폴더 선택으로 바뀌지 않습니다.

## Join 접속 주소 기억과 수정

- 처음 입력한 **IP와 포트**를 실행기 폴더의 `join-settings.json`에 기억합니다. 방 코드는 저장하지 않습니다.
- 다음 실행 때 `[이전 값]`이 표시됩니다. **Enter는 그대로 사용**, 바꾸려면 **새 값을 입력**합니다. 호스트가 알려준 포트를 입력하세요.
- 게임이 열리기 전 접속에 실패하면 **Enter: 같은 값으로 다시 시도 / 2: IP·포트·방 코드 수정 / 3: 종료**를 선택할 수 있습니다. 새 주소로 다시 시도할 때는 현재 방 코드를 입력합니다.
- 변경한 값은 다음 실행에도 남습니다. 실행기를 다른 폴더로 옮길 때는 기존 `join-settings.json`도 함께 복사하세요.
- 진행 중인 게임과 자동 재접속은 현재 방의 주소를 사용합니다. 다른 주소로 변경하려면 현재 세션을 끝내고 Join을 다시 실행합니다.

## 온라인 실행 전 설정

1. 실행기 폴더의 **`Settings-Online.cmd`**를 엽니다. 게임 폴더를 묻는 경우, Host/Join에서 사용하는 것과 같은 폴더를 지정합니다.
2. **`1P 키 설정 — 온라인에서 사용할 키`**에서 각 동작의 오른쪽 칸을 선택하고 원하는 키를 누릅니다. 확인 후 메인 설정 창에서도 **저장**을 누르세요.
3. 화면 크기·소리·화면 갱신·텍스처 화질을 고른 뒤 저장하고, Host/Join을 실행합니다. 이미 진행 중인 게임에는 다음 실행부터 반영됩니다.

**친구도 각자의 PC에서 1P 키를 설정합니다.** 2P·3P 버튼은 한 PC에서 원래 로컬 게임을 할 때의 설정입니다. 온라인은 키보드만 지원하며, 각 PC의 키가 같아도 서로의 캐릭터와 겹치지 않습니다.

온라인 실행기는 화면·소리 설정을 각 PC에서 가져오되 **창 모드로 실행**합니다. 설정 프로그램의 전체 화면 선택은 원래 게임을 직접 실행할 때 적용됩니다. 설정은 로컬 `DATA/SaveData/KeyConfig.v4`와 `SystemConfig.v4`에 기록하며, 온라인 캐릭터 저장과는 별개입니다.

원본 설정 도구는 **`RBOEx3Config.exe`**입니다. 위 CMD는 이를 확인해 같은 폴더에 **`RBOEx3Config-KO.exe`** 한글 사본을 만들고 실행합니다. 원본은 보존합니다. EX3 설정 원본과 Windows 10 1903 이상이 필요하며, 번역된 설정 실행 파일 자체를 배포 ZIP에 포함하지 않습니다.

## 조작

모든 PC에서 **자신의 로컬 1P 키 설정**을 사용합니다. 친구는 접속 순서에 따라 2P·3P가 되므로 로컬 2P·3P 키를 사용할 필요가 없습니다. 모두 같은 Z키를 사용해도 각자의 캐릭터에만 전달됩니다.

| 동작 | 기본 키 |
| --- | --- |
| 위 / 아래 / 왼쪽 / 오른쪽 | H / N / B / M |
| 결정·공격 / 취소·다른 동작 | Z / X |
| 나머지 전투 동작 | C / V |
| 이름 입력 완료 | Q |
| 전투 일시정지 | 1P의 Q 또는 F12 |

기존 키보드 설정을 가져옵니다. 패드나 잘못된 키 번호로 설정된 동작은 온라인 복사본에서 기본 키보드 값으로 바꿉니다. 원본 설정은 수정하지 않습니다. 현재 온라인 패드 입력은 지원하지 않습니다. 게임 창을 선택한 상태에서 조작하세요.

캐릭터 생성 중에는 각자의 입력을 사용하고, 공통 메뉴와 전투 일시정지는 1P가 맡습니다. 게임 자체의 동일 캐릭터 조합 제한은 유지합니다.

## 온라인 저장

- 호스트: 실행기 폴더의 `saves/host/current.json`에 전원의 온라인 저장을 보관합니다.
- 친구: `saves/replicas/<방의 저장 ID>/current.json`에 같은 사본을 보관합니다.
- 각 저장 폴더의 `history`에 이전 저장본도 남깁니다. 검증된 새 저장을 먼저 기록한 뒤 현재 파일을 교체합니다.
- 게임이 캐릭터를 저장할 때 생성·성장 데이터를 수집하고, 세션 상태 일치가 확인된 저장만 호스트와 친구에게 확정합니다. 동기화 오류가 나면 마지막으로 확인된 저장을 유지합니다.
- 다음에 같은 호스트가 실행하면 이 저장을 전원에게 전달합니다. 2인으로 플레이해도 사용하지 않은 세 번째 캐릭터의 저장 슬롯은 보관합니다.
- 캐릭터 슬롯 최대 30개와 지원되는 공통 진행 파일을 보관합니다. 원본 개인 세이브를 가져오거나 덮어쓰지 않습니다.

**업데이트할 때 `saves` 폴더를 보존하세요.** 다른 폴더에 새 버전을 풀었다면 기존 `saves`도 옮겨야 이어서 할 수 있습니다. 새 호스트 PC로 옮기려면 실행기를 모두 종료한 뒤 기존 `saves/host`를 복사합니다. 원래 호스트 저장이 없을 때는 친구의 해당 `replicas/<저장 ID>` 폴더를 새 호스트의 `saves/host`로 복사해 복구할 수 있습니다. 기존 호스트 저장이 있다면 먼저 다른 이름으로 백업하세요.

이는 일반 캐릭터·진행 저장입니다. 전투 중 창을 닫으면 마지막 게임 저장 시점 이후의 진행은 잃을 수 있습니다. 자동 복구는 아래 방식으로 동작합니다.

## 자동 재접속과 복구

- **일시적인 통신 장애:** 전원이 잠시 기다리고 같은 게임 창에서 이어갑니다. 처리되지 않은 입력을 순서대로 재전송하며, 이미 처리한 입력은 중복 적용하지 않습니다. 이 경우 전투 위치와 미저장 진행도 유지됩니다.
- **전투 중 실제 진행 불일치:** 전원이 멈춰 차이를 확인하고, 가능한 경우 같은 게임 창에서 스테이지 시작 지점을 다시 불러옵니다. 검증된 화면 표시 값만 다른 경우에는 계속 진행합니다. 친구는 원래 2P·3P 자리를 유지합니다. **복구 중 실행기 창은 닫지 마세요.**
- **게임 비정상 종료·지원하지 않는 장면·장면 복구 실패:** 게임을 재실행해 복구합니다.
- 스테이지 복구에서는 들어갔을 때의 캐릭터·선택 슬롯·난수를 함께 복원합니다. 그 스테이지 안에서 얻은 미저장 경험치·아이템·이동은 되돌아갑니다. 충돌한 게임의 전투 중 메모리 전체를 복원하는 기능은 아닙니다.
- 마지막으로 전원이 일치한다고 확인한 1P·2P·3P 저장본은 별도로 유지하고 친구 PC에도 전달합니다. 불일치가 난 프레임의 미확정 저장은 반영하지 않습니다.
- 시작 지점이 없는 화면에서 게임이 충돌하거나 짧은 시간에 스테이지 복구가 반복되면 저장본을 유지하고 타이틀로 돌아갑니다. 단순한 연결 재시도는 이 반복 횟수에 포함하지 않습니다.
- 재접속은 최대 약 5분간 시도합니다. 같은 오류가 반복되어 복구가 불가능하면 저장본을 보존하고 종료 이유를 안내합니다.
- 호스트 실행기나 PC 자체가 종료되면 서버도 사라집니다. 이 경우 새 방을 열어 저장 캐릭터로 시작해야 합니다. 게임 창을 사용자가 정상적으로 닫는 동작도 방 전체 종료입니다.

## 한글 패치

한글 싱글 및 온라인 실행 시 자동 적용합니다. 원본 PAC·EXE는 수정하지 않고 임시 게임 복사본에 적용하며, 온라인에서는 참가자의 게임 파일과 한글 패치 버전도 연결 전에 비교합니다.

타이틀·설정·주점·캐릭터 생성·직업·기술·지도·전투 안내·일시정지·결과·순위 등의 그림 글씨 495곳과, 중복을 제외한 대사·메시지 584개(실제 문자열 위치 883곳)를 번역했습니다. 561개 한글 글자 모양을 게임의 여섯 비트맵 글꼴에 추가했습니다. 숫자·HP/SP 등 약어와 작품명·제작진 이름은 필요한 표기를 유지합니다.

이번 범위에서 **부가 메뉴의 제작진·유저 편지 코너는 제외**했습니다. 캐릭터 이름 입력 방식과 원본 음성은 바꾸지 않습니다. 모든 스테이지를 직접 완주하며 대사 표시를 검사한 것은 아니므로, 드문 장면의 줄바꿈·표현은 추가 교정이 필요할 수 있습니다. 한글 패치는 Single-Korean.cmd 및 Host/Join 실행기에서 적용됩니다. 원본 EXE를 직접 실행하면 적용되지 않습니다.

## 인터넷 연결

호스트 PC에 **TCP 47624**가 들어올 수 있도록 공유기 포트 연결과 Windows 방화벽을 설정합니다. 실행기는 이를 자동 변경하지 않습니다. 외부 친구에게 공유기의 **공인 WAN IPv4 주소**와 매번 새로 생성되는 방 코드를 전달하세요. 주소에 `http://`나 `:47624`를 붙이지 않습니다.

게임 창이 뜨기 전 `timed out`이면 서버까지 연결되지 않은 것입니다. 호스트 실행기 대기 여부, 접속 주소, 포트 연결을 확인합니다. 이중 공유기나 CGNAT 환경에서는 추가 설정이 필요할 수 있습니다. 자동 중계 서버는 제공하지 않으며 TCP 통신 자체는 암호화하지 않습니다.

## 종료와 진단

플레이 시간 제한을 두지 않습니다. 온라인 일반 진행에서는 별도의 리플레이 녹화와 그 시간 경고를 끕니다. 캐릭터 저장은 유지됩니다. 참가자 한 명이 게임 창을 닫으면 방 전체가 종료됩니다.

상태 불일치는 계속 감지하고 복구를 시도합니다. `logs`의 해당 실행 폴더에 `bridge.txt`, `result.json`과 프레임 기록을 남깁니다. 호스트의 `events` 폴더에는 연결 복구, 진행 불일치, 각 참가자의 최근 상세 상태가 기록됩니다. 진단 전송에 성공하면 친구에게 파일을 따로 요청하지 않고 양쪽을 비교할 수 있습니다. 기록이나 진단 전송 실패만으로 복구를 중단하지 않습니다. 이 자료는 방의 호스트에게만 전달하며 GitHub 등 외부 서버에는 올리지 않습니다.

같은 창에서의 복구는 `bridge.txt`의 `SCENE_RELOAD_BEGIN/READY`와 호스트 `events`의 `state_inspection`, `stage_restart`에 남깁니다. 프레임 기록의 `epoch`로 복구 전후를 구분하며, 게임을 재실행한 경우에는 `recovery.json`과 `recovery-번호` 폴더도 남깁니다. 스크립트 전체, 현재·다음 동작 기록, 활성 공격 판정 자료를 주소와 분리해 비교합니다. 확인하지 못한 값을 임의로 무시하거나, 다른 진행 상태를 그대로 계속하지 않습니다.

## 검증 범위

한 Windows PC에서 분리된 실제 게임과 TCP 연결로 검사합니다. 캐릭터 생성, 저장 사본 일치, 저장 후 재실행, 1스테이지 전투와 다음 스테이지 전환을 확인했습니다. 2·3인 연결 끊김·진행 불일치·게임 비정상 종료를 주입하여 재접속, 스테이지 시작 상태 복원, 다음 스테이지 진행과 세 캐릭터 저장 보존을 검사했습니다. 클리어 전환 검사는 시간을 줄이기 위해 시험 코드로 클리어 조건을 만들고 원래 게임의 후속 처리를 실행했습니다. 자연 플레이로 보스를 처치하거나 전 스테이지를 완주한 검사는 아닙니다.

게임 전체 메모리를 비교하지 않습니다. 확인된 캐릭터·난수·메뉴 상태와 활성 객체를 검사하며, 프로세스별 주소와 일부 화면 효과 값은 정규화합니다. 서로 다른 PC에서의 장시간 일반 진행, 모든 캐릭터 기술과 스테이지는 추가 검증 대상입니다. [상세 검증 기록](docs/VALIDATION.md)을 참고하세요.
