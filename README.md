# RBO Netplay Lab

**[Windows 시험판 다운로드 — ZIP 약 12MB](https://github.com/frm777777-dot/rbo-netplay-lab/releases/download/v0.3.0/RBO-Netplay-Lab.zip)** · [릴리스 안내](https://github.com/frm777777-dot/rbo-netplay-lab/releases/tag/v0.3.0)

Ragnarok Battle Offline EX3를 **호스트 1명 + 친구 1~2명**이 각자 PC에서 실행하도록 만든 온라인 연결 실험판입니다. 호스트 PC가 서버 역할을 하므로 별도의 유료 서버나 화면 전송 서비스는 사용하지 않습니다.

> **v0.3.0은 플레이 시간 제한을 제거한 2인·3인 고정 시험 스테이지용입니다.** Stage 15, 25레벨 마법사를 선택한 인원만큼 사용합니다. 2인 방에는 세 번째 캐릭터가 등장하지 않습니다. 일반 캐릭터 선택·스테이지 이동·저장·재접속은 아직 지원하지 않습니다. 시간 제한 제거가 전체 게임의 정상 진행을 보장하는 것은 아닙니다.

**호스트와 친구 모두 v0.3.0을 사용하세요.** 이전 v0.1.0·v0.2.0과는 연결되지 않습니다.

## 친구가 실행하는 방법

1. 위 **Windows 시험판 다운로드**를 눌러 `RBO-Netplay-Lab.zip`을 받습니다. GitHub의 `Code → Download ZIP`이나 `Source code` 압축본은 실행용 패키지가 아닙니다.
2. 압축을 완전히 풀고 `Join-Online.cmd`를 실행합니다. Python은 패키지에 포함되어 있어 따로 설치하지 않아도 됩니다.
3. 자신의 게임에서 **일본어판 `rbo_ex3.exe`와 `DATA`가 함께 들어 있는 폴더**를 입력합니다.
4. 호스트에게 받은 **접속 주소와 방 코드**를 입력합니다.
5. 게임 창을 선택한 뒤 **자신의 로컬 1P 키 설정**으로 조작합니다. 친구는 자동으로 2P 또는 3P가 됩니다.

게임 원본은 포함되어 있지 않습니다. 참가자 모두 같은 일본어판 EX3 4.0 실행 파일과 기본판·EX1·EX2·EX3 데이터를 준비해야 합니다. 실행 파일이나 게임 데이터가 다르면 연결을 거부합니다.

## 호스트가 실행하는 방법

1. 같은 압축파일에서 `Host-Online.cmd`를 실행합니다.
2. 플레이 인원을 **본인 포함 2 또는 3**으로 선택합니다. Enter만 누르면 2인입니다.
3. 게임 폴더를 입력하고, 화면에 나온 방 코드와 공유기에서 확인한 **공인 WAN IPv4 주소**를 친구에게 전달합니다.
4. 선택한 인원이 준비되면 시작합니다. 2인 방은 친구 한 명만 접속하면 됩니다. 실행 직후 로고·타이틀 화면에서 약 30초간 준비한 뒤 전투 화면으로 자동 전환됩니다. 준비 중에는 캐릭터를 조작할 수 없습니다.

인원은 방을 만들 때 정합니다. 시작한 방에 인원을 추가하거나, 연결이 끊겼을 때 자동으로 인원을 줄이는 기능은 지원하지 않습니다.

외부 인터넷에서 접속하려면 **TCP 47624**가 호스트 PC로 들어올 수 있어야 합니다. 공유기의 포트 연결과 Windows 방화벽 허용은 별도로 설정해야 하며, 실행기가 자동으로 바꾸지는 않습니다. CGNAT·이중 공유기 환경은 추가 설정이나 가상 사설망이 필요할 수 있습니다. 중계 서버와 자동 포트 개방은 제공하지 않습니다.

주소는 `http://`나 `:47624` 없이 입력합니다. 외부 친구에게는 내부 주소 `192.168.x.x`를 전달하지 않습니다. 조회 사이트의 주소와 공유기 WAN 주소가 다르면 접속 주소를 다시 확인하세요. 게임 창이 뜨기 전 `timed out`은 서버까지 연결되지 않은 경우이며, 호스트가 대기 시간 초과로 종료됐다면 다시 실행하고 새 방 코드를 전달합니다.

## 시간 제한과 종료

기본 실행에는 7,200프레임 제한이나 15분 실행 제한이 없습니다. 기존 데모의 자동 종료 타이머도 해제했습니다. 실시간 입력은 고정 크기 공간을 재사용하므로 원래 데모 기록 길이를 넘어도 계속 전달됩니다.

끝내려면 어느 참가자든 게임 창을 닫으면 됩니다. 연결이 끊기거나 검사 대상 상태가 다르면 세션을 종료하는 기능은 유지합니다. 캐릭터 선택·다른 스테이지·저장 등 기존 미지원 기능은 별도입니다.

## 같은 키를 써도 됩니다

모든 PC에서 로컬 **1P 키 설정**을 읽고, 서버가 연결별로 배정한 캐릭터에게만 전달합니다. 원격 PC의 키보드 이벤트를 그대로 재현하는 방식이 아닙니다.

| PC | 사용하는 키 설정 | 조작하는 캐릭터 |
| --- | --- | --- |
| 호스트 | 자신의 1P 설정 | 1P |
| 친구 A | 자신의 1P 설정 | 2P |
| 친구 B (3인 방) | 자신의 1P 설정 | 3P |

모두 Z를 누르면 각자의 캐릭터가 공격합니다. 기본 설정은 **H/N/B/M 이동, Z/X/C/V 동작**입니다. 기존 키 설정 파일은 시험용 복사본으로 가져옵니다. 기본 Z키는 직접 조작까지 확인했으며, 사용자 지정 키와 패드는 별도 검증이 필요합니다.

## 현재 확인한 범위

- v0.3.0 통신 검사 28개 통과. 무제한 방의 2인·3인 입력 동기화, 호스트 또는 친구의 종료, 상태 불일치 감지, 최근 기록만 유지하는 동작을 포함합니다.
- 실제 게임 2개 × 24,000프레임: 기존 종료 시점과 원래 입력 기록 길이 이후에도 입력·검사 대상 상태 차이 0건.
- 3인 무제한 방: 7,789 공통 프레임의 입력·검사 대상 상태 차이 0건. 사용자의 검사 단축 요청으로 호스트 시험 게임을 종료했고, 세 참가자가 모두 정상 종료했습니다. 계획한 24,000프레임 검사는 완료하지 않았습니다.

이전 v0.2.0 검사:

- 2인·3인 방의 입력 분리, 인원 대기, 정원 초과, 버전 차이 및 종료 처리 등 통신 검사 25개 통과.
- 실제 게임 **2개 × 7,200프레임**의 자동 전투에서 입력·검사 대상 상태 차이 0건, 정상 종료.
- 2인 방의 세 번째 캐릭터 비활성화와 세 번째 입력 0을 매 프레임 확인.
- 동일 Z키를 실제 키 변환 경로에 넣는 2인 × 2,400프레임 검사에서 각자의 캐릭터로만 입력 전달.
- 기존 3인 모드도 게임 3개 × 2,400프레임에서 입력·검사 대상 상태 차이 0건, 정상 종료.
- 실제 호스트·참가 실행기로 2인·3인 방 각각 시작 및 정상 종료 확인. Enter의 기본 2인 선택 포함.

이전 v0.1.0에서는 3인 실제 키보드 조작을 포함한 7,200프레임도 상태 차이 없이 정상 종료했습니다.

사용자가 v0.2.0에서 다른 PC의 친구와 인터넷 접속 후 게임 창이 뜨는 것을 확인했습니다. 외부 환경의 장시간 동기화 기록을 수집한 검사는 아닙니다. 화면에 기존 `DEMONSTRATION` 표시가 남아 있지만 동작 입력은 서버에서 실시간으로 받습니다. 전체 게임 메모리, 모든 스테이지, 인터넷 지연·손실, 다른 PC의 동일 진행을 보장하는 검사는 아닙니다. 자세한 범위는 [검증 기록](docs/VALIDATION.md)에 있습니다.

## 게임 파일과 기록

원본 실행 파일을 디스크에서 수정하지 않습니다. 임시 폴더의 시험용 게임 프로세스에 연결 모듈을 적용하며, 캐릭터 저장을 원본 게임에 되돌리지 않습니다. 접속용 방 코드는 매번 새로 생성됩니다. 현재 TCP 통신 자체는 암호화하지 않습니다.

지원하는 일본어판 EX3 실행 파일 SHA-256:

```text
05b14b047e49dabb026c96150f8d5aab497d20d9b2d52f5e59a8aef1af5b8dc0
```

실행 기록은 압축을 푼 폴더의 `logs`에 남습니다. 이 저장소에는 게임 데이터, 저장 파일, 개인 실행 로그, 접속용 방 코드를 올리지 않습니다. RBO 공식 프로젝트와는 별개의 실험 도구입니다.

무제한 세션의 프레임 로그는 8MiB 파일 최대 3개로 순환하며, 서버는 최근 4,096프레임만 메모리에 보관합니다. 개발용 `--frames N`을 지정하면 정해진 길이의 검사도 가능합니다.
