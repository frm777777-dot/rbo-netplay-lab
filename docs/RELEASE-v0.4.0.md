# v0.4.0 — 캐릭터 선택, 일반 진행, 전원 저장

호스트 PC에 친구 한두 명이 접속해 캐릭터를 선택·생성하고 1스테이지부터 진행할 수 있습니다. 공통 메뉴와 출발·일시정지는 1P가 맡고, 캐릭터 생성과 전투는 각자의 로컬 1P 키를 사용합니다. 같은 키 구성을 써도 입력은 연결별 캐릭터로 분리됩니다.

호스트가 전원의 온라인 세이브를 관리하고 친구 PC에는 검증된 사본을 보관합니다. 이전 저장본은 history에 남습니다. 다음 실행에서는 호스트 저장을 함께 불러옵니다. 원본 게임의 개인 세이브를 덮어쓰지 않습니다. 이는 게임의 일반 저장 기능이며 전투 위치를 재개하는 저장은 아닙니다.

메뉴의 로컬 효과음 종료 시점과 게임 시계 차이가 전환 시점을 바꾸지 않도록 했습니다. 새 전투 검사에서 발견한 명령 자료 포인터는 주소 대신 실제 자료 앞 64바이트를 비교합니다. 상태 불일치 때 양측 비교에 필요한 최근 상태 기록을 남깁니다.

이전 실사용 종료는 48,988프레임의 상태 불일치로 확인됐습니다. 당시 친구의 원시 기록이 없어 정확한 차이 필드는 확정하지 못했습니다. 이번 수정이 모든 장시간 종료를 해결했다고 보장하지는 않습니다.

검증:

- 통신 검사 36개와 저장 검사 3개 통과.
- 실제 게임 3개에서 캐릭터 생성과 1스테이지 전투 5,000프레임 일치, 세 캐릭터 저장 및 전원 사본 일치.
- 저장 복구 후 3인 7,400프레임: 1P 일시정지·재개, 각자 이동, 1→2스테이지 전환, 저장 사본 일치.
- 2인 8,000프레임: 저장 복구와 1→2스테이지 전환, 상태 일치.
- 실제 게임의 캐릭터 데이터를 의도적으로 바꾸자 101프레임에서 상태 불일치 감지.
- 실제 2인 실행기의 기본 인원 선택과 3인 무제한 실행기의 종료 처리 확인.

검사는 한 PC의 분리된 프로세스와 TCP 연결로 수행했습니다. 스테이지 전환 검사는 클리어 조건만 시험 코드로 만들고 원래 게임의 저장·이동 처리를 실행했습니다. 자연 플레이로 보스를 처치하거나 전 스테이지를 완주한 검사는 아닙니다. 서로 다른 PC의 장시간 일반 진행은 추가 검증 대상입니다.

사용법:

1. 호스트와 친구 모두 아래 `RBO-Netplay-Lab.zip`을 받아 완전히 풉니다. Python 포함, 게임 원본 제외입니다.
2. 호스트는 Host-Online.cmd에서 2명 또는 3명을 선택합니다. 친구는 Join-Online.cmd에 호스트 주소와 새 방 코드를 입력합니다. 기존 TCP 47624 연결 설정을 사용합니다.
3. 함께 게임 창이 열리면 1P가 일반 게임을 시작합니다. 캐릭터 화면에서 모두 Z로 참가하고 각자 선택·생성한 뒤 1P가 출발합니다.
4. 업데이트·폴더 이동 시 `saves` 폴더를 보존하세요. 호스트는 `saves/host`, 친구 사본은 `saves/replicas`입니다.

모든 참가자는 v0.4.0이어야 합니다. 이전 버전과 연결되지 않습니다. 일본어판 EX3 4.0 및 같은 본편·확장팩 데이터가 필요합니다. 패드, 전투 중 재합류, 온라인 리플레이는 지원하지 않습니다. 기본 플레이 시간 제한은 없습니다.
