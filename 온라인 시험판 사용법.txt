RBO 2~3인 온라인 실험판 v0.2.0

현재 범위
사용자 PC에서 서버와 1P 게임을 실행하고, 친구 한두 명이 각각 게임을 실행해
접속하는 입력 동기화 실험판입니다. 화면 전송이나 유료 서버는 사용하지 않습니다.
방을 만들 때 본인 포함 2인·3인을 선택합니다. Enter만 누르면 2인 방입니다.
고정된 Stage 15 초기 상태와 선택한 인원만큼의 25레벨 마법사를 사용합니다.
2인 방에서는 세 번째 캐릭터가 등장하지 않고, 입력도 전달되지 않습니다.
호스트와 친구 모두 v0.2.0으로 업데이트해야 합니다. v0.1.0과는 연결되지 않습니다.
기존 DEMONSTRATION 표시가 남아 있지만 실제 조작 입력은 서버에서 받습니다.
일반 캐릭터 선택, 스테이지 이동, 성장 저장, 재접속은 아직 지원하지 않습니다.
기본 7,200 논리 프레임 뒤 자동 종료합니다. 게임 전체의 온라인 완성판이 아닙니다.

같은 키 사용
참가자 모두 자신의 게임 설정에서 1P 키를 사용합니다.
호스트는 1P, 친구들은 접속 순서에 따라 2P와 3P가 됩니다.
친구가 로컬 2P·3P 키를 쓸 필요가 없습니다.
예: 세 PC에서 모두 Z를 공격으로 설정하면 각자의 캐릭터만 공격합니다.
기본 1P 키: H 위 / N 아래 / B 왼쪽 / M 오른쪽 / Z X C V 동작.
기존 KeyConfig.v4/KeyConfig.cdt 설정이 있으면 시험용 복사본으로 가져옵니다.
기본 Z키는 자동 검사와 사용자의 실제 키보드 조작으로 확인했습니다.
패드와 사용자 지정 키는 별도 실기 검증이 필요합니다.

준비
64비트 Windows와 같은 일본어판 RBO EX3 4.0 게임 파일이 필요합니다.
EX3 실행 파일 SHA256:
05b14b047e49dabb026c96150f8d5aab497d20d9b2d52f5e59a8aef1af5b8dc0
기본판과 EX1·EX2·EX3의 DATA/*.PAC가 모두 있어야 합니다.
영문 패치 실행 파일은 메모리 구조가 달라 이번 버전에서 거부합니다.
압축파일에는 게임 파일이 포함되어 있지 않습니다. 각자 준비한 게임을 사용합니다.
Python 실행 구성요소는 포함되어 있어 별도로 설치할 필요가 없습니다.

실행
1. 호스트: Host-Online.cmd 실행.
   본인 포함 2 또는 3을 입력합니다. Enter만 누르면 2인입니다.
   이 프로젝트에는 준비된 runtime/app 게임을 자동으로 사용합니다.
   배포 압축본에서는 rbo_ex3.exe와 DATA가 있는 폴더를 입력합니다.
2. 화면에 나온 방 코드와 접속 주소를 친구에게 전달합니다.
3. 친구: Join-Online.cmd 실행 → 게임 폴더 → 호스트 주소 → 방 코드 입력.
4. 선택한 인원이 준비되면 시작합니다. 2인 방은 친구 한 명만 접속하면 됩니다.
   처음 화면은 약 30초간 표시됩니다.
5. 게임 창에 포커스를 두고 각자 1P 키 설정으로 조작합니다.
6. 한 명이 창을 닫거나 상태 차이가 감지되면 방 전체를 종료합니다.
   도중 참가나 자동 인원 변경은 지원하지 않습니다.

인터넷 연결
기본 포트는 TCP 47624입니다. 서버는 호스트 PC의 모든 IPv4 인터페이스에서 받습니다.
공유기를 쓰면 TCP 47624를 호스트 PC로 연결하고 Windows 방화벽에서 이 프로그램을
허용해야 외부 친구가 접속할 수 있습니다. 이 도구는 방화벽·공유기 설정을 바꾸지 않습니다.
공인 IPv4에서 외부 접속이 가능한 환경을 전제로 합니다. 통신사 CGNAT나 이중 공유기에서는
추가 설정 또는 가상 사설망이 필요할 수 있습니다. 자동 중계 서버는 포함하지 않습니다.
이 PC에서는 127.0.0.1로 검사했습니다. 실제 서로 다른 PC/외부 인터넷은 아직 검증하지 않았습니다.
방 코드는 매번 새로 만들어집니다. TCP 통신 자체의 암호화는 아직 지원하지 않습니다.

검증과 한계
v0.2.0의 2인 자동 전투는 실제 게임 2개 × 7,200프레임을 정상 종료했습니다.
입력·캐릭터 정보·난수·검사 대상 객체 상태의 차이는 0건이었습니다.
두 캐릭터만 활성 상태이고 세 번째 입력이 0임을 매 프레임 확인했습니다.
2인 동일 Z키 검사도 2,400프레임을 정상 종료했습니다. 한 명씩, 마지막에는
두 명이 함께 입력했을 때 각각 지정된 캐릭터로만 전달되는 것을 확인했습니다.
이 검사는 게임의 키 입력 버퍼에 시험 값을 넣어 실제 키 변환 함수를 통과시키며,
물리 키보드를 누르는 실기 검증과는 다릅니다.
기존 3인 모드도 2,400프레임 자동 전투에서 입력·검사 대상 상태 차이 없이 정상 종료했습니다.
인원 대기, 정원 제한, 입력 분리, 오류 처리 등의 통신 검사 25개도 통과했습니다.
이전 v0.1.0에서는 사용자가 실제 Z키로 공격되는 것을 확인했으며,
3인 실제 키보드 입력을 포함한 7,200프레임도 상태 차이 없이 정상 종료했습니다.
장시간 무입력 시험에서는 약 10,425프레임 뒤 기존 데모가 화면을 전환했습니다.
그래서 이 실험판은 제한된 세션만 제공하며 일반 스테이지 진행을 지원하지 않습니다.
전체 메모리나 모든 상황을 검사한 것은 아닙니다. 화면 흔들림·색상 효과와
프로세스마다 달라지는 일부 주소 값은 상태 비교에서 제외합니다.
인터넷 지연·장시간 플레이·다른 PC·패드·키 설정 변경·메뉴/저장은 후속 검증 대상입니다.

파일과 종료
원본 게임 실행 파일을 패치하지 않습니다. 실행 중 시험용 프로세스에만 연결 모듈을 적용합니다.
수정 가능한 설정과 저장 공간은 임시 폴더 rbo-netplay-lab에 분리합니다.
DATA의 PAC 파일은 읽기 전용 용도로 하드링크 또는 복사해 사용합니다.
원본 게임의 캐릭터 저장으로 결과를 되돌리지 않습니다.
검사 기록은 실행 폴더의 logs에 남습니다. 창과 실행기 종료 후 서버도 종료됩니다.
게임이 멈추거나 종료되면 bridge.txt와 result.json을 확인할 수 있습니다.
