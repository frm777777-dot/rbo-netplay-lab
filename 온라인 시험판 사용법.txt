RBO 2~3인 온라인 실험판 v0.4.0

호스트 PC가 서버를 실행합니다. 친구 1명 또는 2명과 플레이할 수 있습니다.
모두 같은 v0.4.0 실행기를 사용하세요. 게임 원본은 따로 준비해야 합니다.
이전 버전과 연결되지 않으며, 게임 전체의 온라인 완성판은 아닙니다.

시작하기
1. 압축을 완전히 풀고 호스트는 Host-Online.cmd를 실행합니다.
2. 본인 포함 2명 또는 3명을 선택합니다. Enter만 누르면 2명입니다.
3. 각자 일본어판 rbo_ex3.exe와 DATA가 있는 EX3 4.0 게임 폴더를 입력합니다.
4. 친구는 Join-Online.cmd에서 호스트 주소와 방 코드를 입력합니다.
5. 전원 연결 후 함께 게임 창이 열립니다. 1P가 타이틀에서 일반 게임을 선택합니다.
6. 캐릭터 화면에서 모두 Z로 참가하고, 각자 캐릭터를 선택하거나 만듭니다.
7. 선택이 끝나면 1P가 공통 메뉴의 출발과 스테이지를 결정합니다.
   첫 지도 선택은 Stage 1입니다. 예전처럼 데모 자동 시작을 기다리지 않습니다.

조작
모든 PC는 자신의 로컬 1P 키 설정을 사용합니다.
친구는 자동으로 2P/3P가 되므로 자신의 2P/3P 설정을 사용할 필요가 없습니다.
같은 Z키를 눌러도 각자 배정된 캐릭터에만 전달됩니다.
기본 이동: H 위 / N 아래 / B 왼쪽 / M 오른쪽.
기본 동작: Z 확인·공격 / X 취소·다른 동작 / C / V.
Q는 이름 입력 완료에 사용하며, 전투 중 일시정지는 1P의 Q 또는 F12입니다.
게임 창을 한 번 선택하고 조작하세요.
키보드 설정은 가져오고, 패드나 잘못된 키 번호는 온라인 복사본에서
기본 키보드 설정으로 바꿉니다. 원본 설정은 바꾸지 않습니다. 패드는 미지원입니다.
캐릭터 생성은 각자, 공통 메뉴와 출발·일시정지는 1P가 조작합니다.
게임 자체의 동일 캐릭터 조합 제한은 유지합니다.

저장과 이어하기
호스트가 모든 캐릭터를 저장하고, 친구 PC에도 같은 사본을 보관합니다.
호스트 저장: 실행기 폴더의 saves\host\current.json
친구 사본: saves\replicas\저장ID\current.json
각 폴더의 history에는 이전 저장본이 남습니다.
게임이 캐릭터를 저장하는 시점에 수집하고, 상태 일치 확인 후 사본을 갱신합니다.
다음 실행에서 같은 호스트의 저장을 전원에게 전달합니다.
2인으로 실행해도 사용하지 않는 세 번째 캐릭터 저장은 보관합니다.
원본 개인 세이브를 가져오거나 덮어쓰지 않습니다.
업데이트할 때 saves 폴더를 보존하세요. 새 실행기 폴더로 옮길 때도 함께 복사하세요.

전투 중의 위치를 그대로 재개하는 저장은 아닙니다.
창을 갑자기 닫거나 연결이 끊기면 마지막 게임 저장 이후의 진행은 잃을 수 있습니다.
재접속은 새 방에서 캐릭터를 다시 선택하는 방식입니다. 전투 중 재합류는 미지원입니다.
호스트 PC를 바꾸면 실행기를 종료한 뒤 saves\host 폴더를 옮기세요.
호스트 저장이 사라졌다면 친구의 해당 replicas\저장ID 폴더를 새 호스트의
saves\host로 복사할 수 있습니다. 기존 host 폴더는 먼저 다른 이름으로 백업하세요.

인터넷 접속
호스트 공유기에서 TCP 47624를 호스트 PC 내부 주소로 연결하고,
Windows 방화벽에서 실행기를 허용해야 합니다. 실행기는 설정을 자동 변경하지 않습니다.
친구에게 공유기에 표시된 공인 WAN IPv4 주소와 방 코드를 전달하세요.
주소에 http:// 또는 :47624를 붙이지 않습니다.
게임 창이 뜨기 전 timed out은 서버 연결 문제입니다. 주소·포트·호스트 대기를 확인하세요.
자동 중계 서버는 제공하지 않습니다. CGNAT·이중 공유기는 추가 설정이 필요할 수 있습니다.
TCP 통신 자체는 암호화하지 않습니다. 방 코드는 매번 새로 생성됩니다.

종료와 문제 확인
플레이 시간 제한은 없습니다. 온라인 일반 진행에서는 리플레이 녹화와 시간 경고를 끕니다.
참가자 한 명이 게임 창을 닫으면 방 전체가 종료됩니다.
문제가 발생해도 마지막으로 확인된 저장은 유지합니다.
logs의 최신 실행 폴더에서 bridge.txt, result.json을 확인하세요.
동기화가 어긋나면 frames.failure.json과 호스트의 divergence.json을 남깁니다.
이전 실사용 종료는 48,988프레임의 상태 불일치였으며 시간 제한은 아니었습니다.
당시 친구 기록이 부족해 정확한 차이 필드는 확정하지 못했습니다.
이번에는 메뉴 전환의 소리 대기와 주소 값 비교 문제를 수정하고 진단 기록을 보강했습니다.

검증 범위
한 PC에서 분리된 실제 게임으로 2인·3인 캐릭터 선택, 1스테이지 전투,
저장 사본 일치, 저장 후 재실행, 다음 스테이지 전환을 검사했습니다.
전환 검사는 클리어 조건만 시험 코드로 만들고 게임 원래 저장·이동 처리를 실행했습니다.
자연 플레이의 보스 처치나 전 스테이지 완주 검사는 아닙니다.
서로 다른 PC의 장시간 일반 진행, 모든 기술·스테이지는 추가 검증이 필요합니다.

게임과 배포
본편·EX1·EX2·EX3 PAC와 일본어판 EX3 4.0이 필요합니다. 게임 파일은 포함하지 않습니다.
